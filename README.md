# JavaTermProject

**패션 상품 옵션별 재고 및 주문 관리 시스템**

Java 기초 기말고사 대체 과제입니다. 같은 티셔츠라도 검정 M은 남아 있고 흰색 L은 품절일 수 있습니다. 상품마다 색상과 사이즈를 조합한 **옵션**을 두고, 어떤 옵션을 입고하거나 주문했는지에 따라 해당 옵션의 재고를 관리합니다.

화면은 **Java Swing**으로 만들었습니다. 화면에서 조회나 저장을 요청하면 Java 코드가 **JDBC**를 통해 **Oracle XE**에 SQL을 보내고 결과를 화면에 표시합니다.

- 과제 보고서의 논리 ERD는 4쪽, 주요 실행 화면은 5~7쪽, 검증 결과는 8쪽에 있습니다. [제출용 보고서 PDF](<보고서/Java 기초 기말고사 대체 과제_2601110288_박수용.pdf>)
- Oracle 테이블과 제약조건을 생성하는 SQL입니다. [SQL 제출본](sql/schema-export.sql)

## 주요 기능

| 화면 | 할 수 있는 일 |
| --- | --- |
| 상품 관리 | 상품명·가격·제조업체를 입력해 등록합니다. 목록을 조회하거나 선택한 상품을 수정·삭제할 수 있습니다. |
| 재고 관리 | 상품의 색상·사이즈별 재고를 조회합니다. 옵션을 선택하고 입고 수량을 입력한 뒤 **입고** 버튼을 누르면 재고가 늘고 입고 이력이 저장됩니다. |
| 주문 관리 | 회원을 선택하고 옵션과 수량을 담아 주문을 등록합니다. 주문 목록에서 주문을 선택하면 상세 수량과 주문 당시 단가를 확인할 수 있습니다. |

## 처음 실행하기

### 1. Maven 프로젝트 열기

실행에는 JDK 17 이상과 접속 가능한 Oracle XE가 필요합니다. IntelliJ IDEA의 **File → Open**에서 `pom.xml`이 있는 프로젝트 폴더를 열고 Maven 프로젝트로 불러옵니다. 프로젝트 SDK를 JDK 17 이상으로 지정합니다. Oracle JDBC 드라이버(`ojdbc11`)는 Maven이 내려받습니다. [Maven 설정](pom.xml)

Maven이 설치된 터미널에서 컴파일을 확인하려면 `pom.xml`이 있는 폴더에서 실행합니다.

```bash
mvn compile
```

### 2. Oracle 테이블과 기준 데이터 준비하기

- **학교 PC의 기존 Oracle을 사용한다면** 과제 테이블 7개를 소유한 계정으로 접속합니다.
- **빈 실습 스키마를 사용한다면** SQL Developer에서 그 계정에 연결하고 `schema-export.sql`을 연 뒤 **스크립트 실행(F5)** 으로 테이블과 제약조건을 생성합니다. [Oracle 스키마 SQL](sql/schema-export.sql)

SQL 제출본에는 테이블 구조만 들어 있습니다. 빈 스키마에서 화면 기능까지 확인하려면 다음 데이터가 필요합니다.

| 확인하려는 기능 | 먼저 필요한 데이터 |
| --- | --- |
| 상품 등록 | `MANUFACTURER`에 등록된 제조업체 |
| 옵션별 재고와 입고 | `PRODUCT`의 상품과 그 상품에 연결된 `PRODUCT_OPTION`의 색상·사이즈 |
| 주문 등록 | `MEMBER`에 등록된 회원과 주문 수량을 충족하는 옵션 재고 |

상품은 Java의 상품 관리 화면에서 등록할 수 있습니다. 새 환경에서 제조업체·회원·상품옵션은 SQL Developer에서 준비합니다. 옵션을 만들면 기본 재고는 0개이며, 재고 관리 화면에서 입고할 수 있습니다.

### 3. JDBC 접속 설정하기

IntelliJ IDEA의 **Run → Edit Configurations**에서 **Application** 설정을 두 개 만들고, 아래에 나오는 연결 확인 클래스와 화면 실행 클래스를 각각 지정합니다. 두 설정에 같은 Oracle 접속 환경 변수를 입력합니다.

| 환경 변수 | 입력값 |
| --- | --- |
| `DB_URL` | 서비스 이름을 쓰면 `jdbc:oracle:thin:@//호스트:포트/서비스이름`, SID를 쓰면 `jdbc:oracle:thin:@호스트:포트:SID` |
| `DB_USER` | 과제 테이블 7개를 소유한 Oracle 사용자 |
| `DB_PASSWORD` | 해당 사용자의 Oracle 비밀번호 |

호스트, 포트, 서비스 이름 또는 SID는 SQL Developer에서 접속에 성공한 연결과 맞춥니다. 실제 접속 정보는 로컬 실행 설정에 보관합니다.

### 4. 연결 확인 후 화면 실행하기

1. **`kr.ac.aikopo.javatermproject.ConnectionCheck`** 를 실행합니다. 콘솔의 `Oracle JDBC 연결 성공`과 `확인한 테이블: 7/7`을 확인합니다. 이 프로그램은 접속한 스키마와 과제 테이블 목록을 조회합니다.
2. **`kr.ac.aikopo.javatermproject.ProductManagementApp`** 을 실행합니다. 상품 관리, 재고 관리, 주문 관리 탭이 표시됩니다.

| 실행 중 나타난 상황 | 확인할 곳 |
| --- | --- |
| Maven이 소스 파일을 찾지 못함 | `pom.xml`이 있는 폴더에서 빌드했는지 확인합니다. Java 소스 루트는 `src/`입니다. |
| Oracle에 연결되지 않음 | 현재 실행 설정에 환경 변수 3개가 입력되어 있는지, SQL Developer의 연결 방식과 값이 같은지 확인합니다. |
| JDBC 연결은 성공했지만 테이블이 7개보다 적음 | 콘솔의 현재 스키마와 실제 테이블을 만든 계정을 대조합니다. |
| 제조업체·회원·옵션 선택 목록이 비어 있음 | 해당 계정에 2단계의 기준 데이터가 있는지 확인한 뒤 화면을 새로고침합니다. |

## 화면에서 기능 확인하기

1. **상품 관리**에서 테스트 상품을 등록합니다. **새로고침**으로 목록에서 확인한 뒤 해당 행을 선택해 가격을 바꾸고 **수정**을 누릅니다. 삭제를 시험할 때는 상품옵션이 연결되지 않은 테스트 상품을 선택합니다. 옵션이 연결된 상품의 삭제를 시도하면 삭제할 수 없는 이유를 안내합니다.
2. **재고 관리**에서 색상과 사이즈가 표시된 옵션을 선택합니다. 수량을 입력하고 **입고**를 누른 뒤 해당 옵션의 현재 재고가 늘었는지 확인합니다.
3. **주문 관리**에서 회원과 옵션을 선택하고 수량을 입력한 뒤 **옵션 담기**를 누릅니다. 필요한 옵션을 담고 **주문 등록**을 누릅니다. 정상 주문은 목록과 상세에서 확인할 수 있습니다. 재고보다 많은 수량으로 별도 주문을 시도하면 재고 부족 안내가 표시됩니다.

## DB 설계와 주문 처리

| 테이블 | 저장하는 내용 |
| --- | --- |
| `MANUFACTURER` | 상품을 공급하는 제조업체 |
| `PRODUCT` | 상품명, 가격, 제조업체 |
| `PRODUCT_OPTION` | 상품의 색상, 사이즈, 현재 재고 |
| `MEMBER` | 주문 회원 |
| `SALES_ORDER` | 주문 회원과 주문 일시 |
| `ORDER_ITEM` | 주문한 옵션, 수량, 주문 당시 단가 |
| `STOCK_HISTORY` | 옵션별 입고·출고 수량과 시각, 출고에 연결된 주문상세 |

상품 하나에 여러 옵션을 연결하고, 주문 하나에 여러 주문상세를 연결합니다. 주문 목록의 합계는 각 상세에 저장한 **수량 × 주문 당시 단가**를 더해 구합니다. 입고 이력(`IN`)은 해당 옵션에 연결하고, 정상 주문의 출고 이력(`OUT`)은 해당 주문상세에도 연결합니다.

주문 저장, 재고 차감, 주문상세 저장, 출고 이력 저장은 **한 트랜잭션**에서 처리합니다. 재고를 차감하는 시점에 Oracle의 현재 수량을 확인합니다. 한 옵션이라도 수량이 부족하면 같은 주문에서 앞서 처리한 재고와 기록도 함께 롤백합니다.

## 실행 화면과 검증 결과

| 보고서의 실행 화면 | 기존 학교 PC 검증에서 확인한 내용 |
| --- | --- |
| 5쪽 그림 2 · 상품 관리 | 상품번호, 이름, 가격, 제조업체가 표시된 목록 |
| 6쪽 그림 3 · 재고 관리 | 색상·사이즈별 현재 재고와 입고 입력란 |
| 7쪽 그림 4 · 정상 주문 | 주문 1023, 주문상세 2건, 합계 79,500원 |
| 7쪽 그림 5 · 재고 부족 | 재고가 1개인 옵션 1006에 2개를 요청했을 때의 안내 |

정상 주문 뒤 별도 Oracle 조회에서 옵션 1005의 재고가 **9 → 7**, 옵션 1006의 재고가 **4 → 1**로 바뀌었고, 주문상세마다 출고 이력이 한 건씩 저장된 것을 확인했습니다. 두 번째 옵션에서 재고가 부족한 별도 JDBC 시험에서는 먼저 처리된 재고 차감과 주문상세·출고 이력도 롤백됐습니다. 상품 CRUD, 입고, 주문 시험의 세부 결과는 보고서 8쪽에 있습니다. [검증 보고서](<보고서/Java 기초 기말고사 대체 과제_2601110288_박수용.pdf>)

SQL 파일은 SQL Developer의 **Database Export**로 생성한 DDL을 정리한 결과입니다. 기존 Oracle 스키마와 테이블·제약조건을 대조했습니다. 별도 스키마에서 이 파일을 실행해 재현하는 작업은 미검증입니다.

## 폴더와 주요 파일

```text
JavaTermProject/
├─ README.md
├─ pom.xml
├─ .gitignore
├─ src/kr/ac/aikopo/javatermproject/
├─ sql/schema-export.sql
└─ 보고서/                         제출용 PDF
```

`pom.xml`의 `sourceDirectory`가 Maven의 Java 소스 루트를 `src/`로 지정합니다. 그 아래 경로는 Java 패키지 `kr.ac.aikopo.javatermproject`에 맞춰 구성했습니다.

| 파일 | 역할 |
| --- | --- |
| `ProductManagementApp.java`, `ProductRepository.java` | 앱 실행과 상품 관리 화면, 상품·제조업체 조회 및 상품 저장 |
| `InventoryPanel.java`, `InventoryRepository.java` | 재고 관리 화면, 옵션별 재고 조회와 입고 처리 |
| `OrderPanel.java`, `OrderRepository.java` | 주문 관리 화면, 주문 목록·상세 조회와 주문 트랜잭션 |
| `ConnectionCheck.java`, `Database.java` | Oracle 연결 확인, 환경 변수 기반 JDBC 접속 |

IntelliJ의 로컬 실행 설정(`.idea/`), Maven 빌드 결과(`target/`), 편집용 한글 파일과 원본 캡처는 로컬에서 관리합니다. 실행 화면은 제출용 PDF에 포함되어 있습니다.
